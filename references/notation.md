# 業務フロー記法リファレンス（BPMN 簡易セット・分析レベル）

## 準拠する標準

- デジタル庁「地方公共団体の基幹業務システムの標準仕様における業務フローについて」（令和3年9月）
- J-LIS「地方公共団体の情報システム調達における機能要件の表記方法利用ガイド」（平成27年3月）

### 記載の原則

- **事務単位**でプールを作る（「証明書の交付」「新規登録」など。業務＞事務＞作業 の3階層の「事務」）
- **分析レベル**で書く: 基本作業＋事務詳細（注記）＋例外処理 を表記する
- 作業は「**何を使って何をする**」の粒度。「ファイルを開く」「コピペする」までは落とさない
- 各作業に **3桁の作業番号**（001, 002, ...）を振る
- システム化対象の作業は、脚注に**作業番号と機能要件番号の対応表**を書ける（footer）

## 使用する記号（簡易セット）

| type | 記号 | 意味 |
|---|---|---|
| `start` | 細線の円 | 開始イベント |
| `end` | 太線の円 | 終了イベント（例外終了にも使う） |
| `task` | 角丸四角＋作業番号 | 作業 |
| `gateway` | ひし形（×） | 排他分岐。分岐条件は label に書く |
| `datastore` | 円柱 | システム・データベース（基幹システム等） |
| `dataobject`（旧 `document` も可） | 角折れの小アイコン＋横ラベル | 書類・メール・添付データ等。**線ではつながず**、関連する流れの近くに置く |
| `annotation` | ブラケット［＋テキスト | 事務詳細・制約事項・例外処理の注記 |

線（flows）:
- **シーケンスフロー**（実線・矢印）: 作業の順序。type 省略時
- **アソシエーション**（破線・矢印なし）: 注記・システム（円柱）との関連。`"type": "association"`。**データオブジェクトにはつながない**

## フロー定義JSONスキーマ

```json
{
  "title": "証明書の交付",
  "lanes": [
    { "id": "jumin", "pool": "住民", "name": "" },
    { "id": "madoguchi", "pool": "担当課", "name": "窓口" },
    { "id": "backyard", "pool": "担当課", "name": "バックヤード" }
  ],
  "nodes": [
    { "id": "start", "type": "start", "lane": "madoguchi", "col": 1 },
    { "id": "t001", "type": "task", "no": "001", "label": "受付", "lane": "madoguchi", "col": 2 },
    { "id": "gw1", "type": "gateway", "label": "抑止対象者か", "lane": "backyard", "col": 7 },
    { "id": "ds1", "type": "datastore", "label": "基幹システム", "lane": "backyard", "col": 6, "row": 1 },
    { "id": "doc1", "type": "dataobject", "label": "申請書", "lane": "jumin", "col": 2, "dy": -20 },
    { "id": "note1", "type": "annotation", "label": "〇本人確認書類\n・マイナンバーカード 等", "lane": "jumin", "col": 4, "width": 170 }
  ],
  "flows": [
    { "from": "start", "to": "t001" },
    { "from": "gw1", "to": "end-ex", "label": "Yes" },
    { "from": "t004", "to": "t005", "fromSite": "bottom", "toSite": "top" }
  ],
  "footer": "【対応する機能要件】\n005 対象者照会 ⇔ No.3 照会機能"
}
```

### lanes

| フィールド | 必須 | 説明 |
|---|---|---|
| `id` | ✓ | ノードから参照するID（英数字） |
| `pool` | ✓ | プール名（同じ pool 名の連続するレーンが1プールにまとまる） |
| `name` | ✓ | レーン名。プールにレーンが1本だけなら `""` にするとレーン帯を描かない |
| `height` | - | レーン高さ(pt)の手動指定。省略時は row 数から自動計算 |
| `gapBefore` | - | このレーンが**プールの先頭**のとき、直前プールとの隙間(pt)を個別指定。開始プール（住民等）を大きく離して見せたい時に使う（例: 50） |

プール間の隙間はルート直下の `poolGap` で全体一括でも変えられる（既定 30pt）:

```json
{ "title": "...", "poolGap": 40, "lanes": [...], ... }
```

### nodes

| フィールド | 必須 | 説明 |
|---|---|---|
| `id` | ✓ | flows から参照するID |
| `type` | ✓ | start / end / task / gateway / datastore / dataobject（旧 document も可）/ annotation |
| `lane` | ✓ | lanes の id |
| `col` | ✓ | 時系列の列位置（1始まり） |
| `row` | - | レーン内の縦位置（0始まり・省略時0）。datastore を作業の下に置くときは row: 1 |
| `label` | task等 | 表示テキスト。annotation は `\n` で改行できる |
| `no` | - | task の作業番号（"001" など）。入れるかどうかは最初に利用者に確認（手修正が多い場合は番号なし推奨） |
| `width` | - | 幅(pt)の上書き。task(既定88)・datastore(ラベル長で自動)・dataobject(56)・annotation(130) |
| `height` | - | task の高さ(pt)の上書き。ラベルに `\n` を含むと自動で高さが増える。省略時は、枠幅に収まらない長さのラベルを生成スクリプトが均等改行（バランス折り返し。孤立1文字だけの行を作らない）してから行数に応じて高さを決める。さらに描画後に実測して事前見積もりより大きければ高さを自動拡張する保険もかかる（レーン高さも同様に事前見積もりで拡張される） |
| `dx` / `dy` | - | 全ノード共通の位置微調整(pt)。グリッド位置から右/下へずらす。dataobject を関連する流れの線に寄せる等に使う |

### flows

| フィールド | 必須 | 説明 |
|---|---|---|
| `from` / `to` | ✓ | nodes の id |
| `type` | - | 省略=シーケンスフロー / `association`=破線 |
| `label` | - | 分岐条件（Yes / No など）。中点付近に置かれる |
| `fromSite` / `toSite` | - | 接続辺の強制指定: top / left / bottom / right。省略時は自動（最短ルート） |

## レイアウト規約（col / row の割り当て方）

1. **1列1ステップ**。時系列に沿って col を 1 から順に振る
2. **開始イベントは col 1**、メインの終了イベントは最終列
3. レーンが変わっても col は共通の時間軸として通しで使う（上下のレーンで同じ col は「同じタイミング」）
4. **datastore は関連する task と同じ col の row: 1**（真下）に置く
5. **dataobject は関連する流れの線の近くに置き、association ではつながない**（`dx` / `dy` で線際に寄せる）。annotation は関連する作業と近い col の住民レーン等に置く
6. gateway の分岐先: Yes/No の行き先は次の col 以降に置く。例外終了はゲートウェイの隣の col
7. 例外終了イベントには annotation（例外処理の説明）を隣の col に添えて association で結ぶ
8. 同一レーン内で縦に並べたいものだけ row を増やす。むやみに row を使わない（レーンが太る）
9. **annotation は関連ノードと同じレーンの近い col に置く**。別プールに置くと破線が図を長距離横断して読みにくい
10. **分岐ラベル（flows の label）は短い言葉にする**（2〜6文字目安。「県道・国道」「Yes」等）。ラベルは線の出口近くに自動配置される
11. **task の label は8文字程度まで**を目安にする。それを超える長さでも、生成スクリプトが枠幅に合わせて自動で均等改行（バランス折り返し）するため描画は破綻しないが、読みやすさのためには名前を短くして詳細は annotation に逃がすのが望ましい。`\n` による明示改行も引き続き使える（意味的な区切りとして必ず尊重され、そのセグメント内だけで均等折り返しがかかる）
12. 長い縦断コネクタ（例: 下のレーンから市民レーンの受領タスクへ戻る線）が通る col には annotation 等を置かない（線がテキストを横切る）

## 生成スクリプトの仕様メモ

- `scripts/generate-flow.ps1`（PowerShell 5.1 以上 + Excel COM。完全ローカル）
- フォント: Meiryo UI / 配色: 白黒 / 用紙: 印刷前提なし（PDF検証用にA4横1ページのフィット設定のみ）
- コネクタは図形に接続済み。手修正で図形を動かせば線が追従する
- 経路の既定: 同一レーン内は最短ルート自動。**レーンをまたぐ順序フローは横から出て横に入る**（真下の書類・システムとの衝突回避）。ゲートウェイ発の分岐だけは最短ルート（下方向の枝は下辺から出る）
- コネクタの経路が変なときは fromSite / toSite を明示すると直ることが多い
- ゲートウェイの条件ラベルはひし形の上に置かれる。レーン上端に余白がない場合は自動で左下に回る
- 動作確認用サンプル: `assets/sample-flow.json`（デジ庁の記載例「証明書の交付」を再現したもの）
- 人/システムの marker 記号は使わない。dataobject（旧 document）は association で結ばず、関連する流れの線の近くに `dx` / `dy` で寄せて表示する
- task ラベルの折り返し: 枠幅に収まらない場合、生成スクリプトが推定文字幅から「各行の幅がなるべく均等になる」位置で改行を挿入する（孤立1文字だけの行を作らない）。`\n` による明示改行はセグメント境界として必ず尊重され、そのセグメント内だけで均等折り返しがかかる。行頭に句読点・拗促音・閉じ括弧類が来る、行末が開き括弧類になる、といった分割は簡易的な禁則処理で1文字ずらす

## 既知の制限（v1）

- 差し戻しループ・線の交差回避の自動レイアウトはしない（手修正前提）。レーンを何段もまたぐ長い縦断の戻り線も同様に手修正前提
- 既存Excelフロー図の読み取り（As-Is取り込み）は未対応
- メッセージフロー（プール間の封筒付き破線）は association で代用
